Standard Event Flow (Per Keystroke)
When a user presses a key, the standard sequence of events emitted by the OS and routed by Tkinter proceeds as follows:
<KeyPress>: The key is initially pressed down.
<Key> (or <KeyRelease>): The event is fully registered and dispatched.

return "break" (Optional): If you return the string "break" from your callback function, Tkinter stops the event propagation entirely. The default class bindings and broader application-level bindings will not receive the event.

i want to know what happens if a new key event happens while the old is not finished
In Python's standard Tkinter environment, events do not interrupt each other because Tkinter runs on a single-threaded event loop (root.mainloop()).
If a new key event occurs while an old key event's callback function is still executing, the new event is placed into an event queue and waits its turn. 
The Step-by-Step Processing Flow
Key 1 Pressed: Tkinter pauses the event loop and enters the callback function for Key 1.
Key 2 Pressed (While Key 1 Function Runs): The operating system captures Key 2 and places it at the back of Tkinter's internal event queue.
Key 1 Function Finishes: Control returns back to the Tkinter event loop.
Key 2 Processed: Tkinter pulls Key 2 from the front of the queue and executes its respective callback.
The Consequences of Long-Running Functions
Because of this sequential, single-threaded processing, you will experience specific behaviors if a callback takes too long to finish: 
UI Freezing: The entire graphical user interface becomes unresponsive while the first function runs. Buttons cannot be clicked, and windows cannot be resized. 
Laggy Input / Buffer Accumulation: If a user holds down a key or types quickly while the UI is frozen, all those keystrokes accumulate in the queue. Once the first function finally finishes, Tkinter will rapidly fire all the queued events back-to-back, causing a "machine-gun" effect of delayed text or actions.
How to Handle Heavy Tasks Without Freezing
If your key event needs to trigger a long calculation or a network request, you must prevent it from blocking the event loop using one of two methods:
Use Threads (threading.Thread): Run the heavy work in a background thread so the main Tkinter thread can immediately return to the event loop and accept new keys.
Use root.after(): Break long tasks into smaller, incremental steps that schedule themselves to run a few milliseconds later, allowing the event loop to breathe in between steps.

Das fühlt sich oft genau so an, aber unter der Haube von Tkinter ist das technisch unmöglich. Tkinter läuft in einem einzigen Thread (Single-Threaded). Das bedeutet: Python kann immer nur eine einzige Zeile Code gleichzeitig ausführen. Eine Funktion kann sich nicht selbst unterbrechen, um eine andere Funktion zu starten. 
Wenn es in Ihrem Programm so aussieht, als ob das zweite Event das erste pausiert, liegt das fast immer an einer von drei versteckten Ursachen im Code:
1. Sie nutzen root.update() in einer Schleife
Wenn Ihre erste Event-Funktion eine Schleife (z. B. while oder for) enthält und darin root.update() aufgerufen wird, passiert Folgendes: 
Sie zwingen Tkinter manuell, die aktuelle Funktion kurz einzufrieren, das Event-Verzeichnis zu prüfen und neue Tastendrücke sofort zu verarbeiten.
Wenn Sie in diesem Moment Taste 2 drücken, springt Tkinter sofort in die Funktion von Taste 2, arbeitet diese komplett ab und kehrt erst danach zur Schleife von Taste 1 zurück. Das wirkt optisch wie eine Pause.
2. Die Funktionen teilen sich dieselbe Variable
Wenn beide Tasten dieselbe globale Variable oder dasselbe Objekt verändern, überschreiben sie sich gegenseitig.
Beispiel: Taste 1 startet eine Bewegung und setzt richtung = "links". Wenn Taste 2 gedrückt wird, wartet sie brav in der Warteschlange. Sobald sie an der Reihe ist, setzt sie richtung = "rechts". Für Sie sieht es so aus, als ob Taste 2 die Bewegung von Taste 1 "gestoppt" oder pausiert hat. In Wirklichkeit wurde die Variable einfach im Nachhinein überschrieben.
3. Das Betriebssystem sendet Dauerfeuer (Key Repeat)
Wenn Sie eine Taste gedrückt halten, sendet Ihr Betriebssystem nicht ein einzelnes Event, sondern ein kontinuierliches Signal (Press, Press, Press).
Wenn Sie nun kurz Taste 2 antippen, schiebt sich dieses Event in die Warteschlange.
Wenn Ihr Code durch Taste 2 blockiert oder verändert wird, bricht die logische Kette von Taste 1 scheinbar ab.

Das ist eine der bekanntesten Stolperfallen in Tkinter.
Was genau bei root.update() passiert
Wenn Sie root.update() innerhalb einer Funktion aufrufen, sagen Sie Tkinter: „Unterbrich kurz meine aktuelle Arbeit, schaue in die Warteschlange und verarbeite sofort alle ausstehenden Events (wie Mausklicks, Tastendrücke oder Fenster-Aktualisierungen).“
Das führt zu folgendem Ablauf:
Taste 1 wird gedrückt → Funktion 1 startet.
Funktion 1 läuft bis zur Zeile root.update().
Wenn Sie genau in diesem Moment Taste 2 gedrückt haben, sieht Tkinter dieses Event in der Warteschlange.
Tkinter pausiert Funktion 1 auf unbestimmte Zeit und springt sofort in Funktion 2.
Funktion 2 läuft komplett durch.
Erst wenn Funktion 2 komplett beendet ist, springt Python zurück zu Funktion 1 und macht hinter dem root.update() weiter.
Warum root.update() gefährlich ist (Verschachtelung)
Wenn Funktion 2 ebenfalls root.update() aufruft und Sie eine dritte Taste drücken, pausiert Funktion 2, Funktion 3 startet, und so weiter. Das nennt man Reentrancy (Wiedereintrittfähigkeit).
Es führt fast immer zu unvorhersehbaren Fehlern (Bugs), Abstürzen oder dazu, dass Variablen plötzlich unerwartete Werte haben.
Die Lösung: Wie Sie es richtig machen
In Tkinter sollten Funktionen sofort (innerhalb von wenigen Millisekunden) fertig sein und den Thread wieder für root.mainloop() freigeben. Lange Schleifen mit root.update() sind ein Anti-Pattern.
Nutzen Sie stattdessen die Methode root.after(). Diese registriert eine Funktion, die nach einer bestimmten Zeit im normalen Event-Loop aufgerufen wird, ohne den Thread zu blockieren.

def lange_schleife():
    for i in range(100):
        # Macht etwas...
        root.update() # <--- Verursacht die unerwünschte Pause/Unterbrechung
        time.sleep(0.05)

Durch den Aufruf von root.update() unterbrechen Sie die aktuelle Funktion manuell und zwingen Tkinter, sofort in die Event-Warteschlange zu schauen. Dieses Verhalten nennt man Verschachtelung von Events (Event Nesting). Es birgt große Risiken, wie z. B. unvorhersehbare Programmabstürze oder das Erreichen des maximalen Rekursionslimits in Python.
Die Lösung: Ersetzen Sie root.update() durch .after()
Um dieses Problem sauber zu lösen, sollten Sie in Tkinter niemals while-Schleifen in Kombination mit root.update() für Animationen oder wiederkehrende Aufgaben nutzen. Verwenden Sie stattdessen die eingebaute Methode root.after().

Richtig (Der Tkinter-Weg mit .after()):
Mit .after() führt Tkinter ein kurzes Stück Code aus, gibt die Kontrolle sofort wieder an die Event-Schleife ab und führt den nächsten Schritt erst wenige Millisekunden später aus. Events können sich so nicht mehr gegenseitig blockieren oder einfrieren.

import tkinter as tk

root = tk.Tk()

# Eine Kontrollvariable, um zu sehen, welche Bewegung aktiv ist
aktiver_task = None

def bewege_schritt(zaehler):
    global aktiver_task
    if zaehler < 100:
        print(f"Bewege Schritt {zaehler}")
        # Hier Ihre Logik einfügen (z.B. label.place...)
        
        # Plant den nächsten Schritt in 50 Millisekunden
        aktiver_task = root.after(50, bewege_schritt, zaehler + 1)

def taste_gedrueckt(event):
    global aktiver_task
    # Optional: Vorherige Bewegung abbrechen, falls gewünscht
    if aktiver_task:
        root.after_cancel(aktiver_task)
        
    print(f"Taste {event.char} startet eine saubere Bewegung.")
    bewege_schritt(0)

root.bind("<Key>", taste_gedrueckt)
root.mainloop()

Volle Kontrolle: Sie können mit root.after_cancel() eine laufende Bewegung sofort stoppen, wenn eine neue Taste gedrückt wird (wichtig für Spiele oder Steuerungen).
